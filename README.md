# FlowTV

**FlowTV** is a Flutter-based IPTV player project for Android and Windows. It focuses on a polished dark glass UI and on making playback controls easy to reach when the network is unreliable.

> FlowTV is a player, not a broadcaster. Import streams you are authorized to view. A channel appearing in a playlist does not prove that the stream is authorized, online, or available in your country.

## Build verification status

The source archive and workflow configuration have been checked locally. This workspace does not have the Flutter SDK or Inno Setup compiler installed, so an APK/Windows executable/installer and Flutter widget/unit tests have **not** been built/run here. The bundled GitHub Actions workflows run the parser tests and real platform builds; download artifacts only after those workflows report success.

## Included in this source package

- Dark Neon, Light, and Purple Glass themes; accent colors, translucent panels, and animation toggle.
- Home dashboard with channel count, favorites, recent history, quick category sources, and a responsive channel library.
- M3U/M3U8 URL importer and local file picker; `tvg-logo`, `group-title`, `tvg-id`, and `tvg-name` parsing.
- Search, category chips, A–Z sorting, favorites, recently watched, and on-device library persistence.
- Black video canvas, play/pause, mute, source-resolution indicator, subtitle selection, orientation lock, quick quality controls, and playback diagnostics. Windows also has an always-on-top mini-player mode that can be toggled back to the previous window size. Android controls auto-hide after three seconds; Windows controls stay visible for ten seconds and the player settings panel is scrollable.
- Playback profiles: Smart Auto, Data Saver, Balanced, Best Quality, and Manual; buffer profile and automatic reconnect controls.
- HLS bitrate preference through the MPV backend. After sustained buffering, Smart Auto can retry with the lowest advertised HLS rendition if the source exposes multiple renditions.
- Local display downscaling controls. **Downscaling changes the local output only; it does not reduce network data already received.**
- HTTP proxy field for a local V2Ray HTTP proxy endpoint, separate from the OS-level VPN/TUN settings.
- Custom app icon, themed animated toast messages, responsive player connecting/buffering state, and GitHub Actions workflows that build Android APKs, a portable Windows bundle, and a Windows Setup installer.

## Quality-selection behavior (important)

FlowTV does not invent 720p/1080p versions when a source only provides 576p. The player reads reported source/track height and disables options above the reported maximum. For HLS master playlists, the MPV `hls-bitrate` option asks the source/player backend to prefer a rendition by bitrate. Not every IPTV feed exposes a multi-quality HLS master playlist, and a fixed transport stream/MP4 cannot become a genuinely lower-bitrate Internet source just because the app menu says 360p.

The **Local display downscale** feature is different: it can lower the output resolution on the device, but does not lower the incoming bitrate. This is useful for output/rendering experiments, not a data-saving substitute.

The current Smart Auto policy starts with the source's highest advertised HLS rendition and, after sustained buffering, retries with the lowest rendition. If a source does not offer alternatives, the player can only buffer/reconnect; the app cannot conjure a smaller stream. The estimated-data counter is explicitly approximate, not a measurement of your carrier's actual billing.

## V2Ray / proxy notes

- The playback engine is MPV via `media_kit`. The app's proxy field is for an HTTP proxy endpoint, for example `http://127.0.0.1:10809`, if that is the local HTTP port provided by your own client. Use the actual port shown in your V2Ray client.
- A SOCKS-only endpoint is not the same as an HTTP proxy. Do not paste a SOCKS port into the HTTP proxy field.
- Proxy behavior depends on the protocol/backend used by a given stream; some providers use non-HTTP protocols or have their own authentication/region restrictions.
- The importer can also use an HTTP proxy, but a large playlist import may take a while. Prefer focused category playlists over very large global index playlists on a slow connection.
- FlowTV does not include a V2Ray core or VPN tunnel. It uses a proxy already running on the device; system-wide routing still belongs to the V2Ray client.

The Android and Windows runner scaffolding is generated by GitHub Actions using the current stable Flutter SDK. This keeps platform boilerplate aligned with the Flutter version used for the build.

## Build using GitHub Actions (no local Flutter installation needed)

1. Download and extract the `FlowTV-Source-Updated.zip` archive.
2. Create a new **empty** repository on GitHub, for example `flowtv-player`.
3. Upload the *contents* of the extracted folder to the repository root. Keep the hidden `.github` directory and its `workflows` files in place. Do not upload just the ZIP file by itself.
4. Commit the files to the `main` branch (or `master`). GitHub Actions should start the two workflows automatically. You can also open **Actions** and run a workflow manually with **Run workflow**.
5. When a workflow finishes successfully, open that workflow run, scroll to **Artifacts**, and download:
   - `FlowTV-Android-APKs` — APKs split by CPU ABI; choose the matching APK (on most modern Android phones, `arm64-v8a`).
   - `FlowTV-Windows-Installer` — a Windows `FlowTV-Setup.exe` setup program with license acceptance, install-location choice, optional desktop shortcut, Start Menu shortcut, and normal uninstall support.
   - `FlowTV-Windows-x64` — a portable ZIP containing the `.exe` and supporting Flutter/native DLLs. Extract the entire ZIP before launching; do not copy the EXE out by itself.

No signing key is included. Android APKs are CI release builds for direct testing, not a Play Store-signed release. A Windows code-signing certificate is also not included.

### If GitHub Actions does not start

- Check that `.github/workflows/build-android.yml` and `.github/workflows/build-windows.yml` exist in the repository at those exact paths.
- In the repository's **Actions** tab, make sure Actions are allowed.
- Open the failed run and inspect the first red step. The workflows run `flutter create`, `flutter pub get`, icon generation, and the actual release build in CI.

## Run locally (optional)

Install the current stable Flutter SDK and the Android/Windows toolchains. From this folder, generate runner directories into a temporary folder and copy them into the project before running `flutter pub get`, icon generation, and `flutter run`. A simple way to follow the same process as CI is to use the commands shown in the workflow and then run `python tool/patch_platforms.py android windows`.

## Android PiP and orientation

The Android manifest permits cleartext HTTP to keep some older stream URLs usable; prefer HTTPS where possible because plain HTTP can be observed or modified in transit. The Android workflow patches the generated `MainActivity` with a small method channel that calls the platform Picture-in-Picture API on supported Android versions (API 26+). Rotation lock uses Flutter's orientation APIs. Actual PiP availability, supported aspect ratios, and background playback behavior still depend on Android version/device policy and must be tested on the target phone.

## Privacy

Playlist URLs, favorite IDs, recent channel IDs, and settings are stored locally on the device. The app does not include analytics, account sign-in, a backend, ads, or a hosted channel directory. Loading a playlist or channel contacts that source's server (and the configured proxy if enabled).
